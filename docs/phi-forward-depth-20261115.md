# PHI 转发链的迭代证明

基线 `3238aea`。接续批量路径使用检查复用，处理大组合样本在低位地址投影中的
转发链深度拒绝。目标仍是清楚呈现混淆前的业务逻辑，本轮不代表该目标已经达到。

## 实现边界

原独立诊断在第一次投影查询中确认：已定义性检查到第33层，节点仅74/256；失败值为
单实际入边的历史转发 PHI。定义检查改为迭代后，查询能继续到第三次投影，随后关系
检查也在同类转发链触及深度33。最终实现同时处理这两类尾部转发。

- 关系检查只对原 `strip` 已检查的低位恒等转换和转发 PHI 使用迭代；仍检查位宽、
  flags、所有实际入边及该 PHI 处的支配可用性。普通配对 PHI 仍递归逐边证明。
- 已定义性检查只迭代完整单实际入边且输入在 PHI 处可用的转发；每个原始节点和边
  全部保留在定义图中，SCC 的真实种子检查不变。其它算术、普通/重复入边 PHI 仍
  使用原递归检查。
- 共享节点256、深度32、work65536及根搜索上限均不提高。转发节点/关系对照常计数，
  只是相应尾调用不再新建递归层；额外可用性检查也计费。失败的 pair 状态不跨实例
  复用，不新增 freeze、noundef、noalias 或内存事实。只改原先允许的纯 SSA Use。

## 真实结果与剩余问题

两个冻结正式 SDK、原配置/预算共四次静态接口回放：普通大 Flatten 保持闭合，
raw/guarded/loop/clean在两后端均与上一版逐字节相同，work747549→747565，额外16
是新增可用性检查费用。其余证明统计不变。组合档仍为closed0，work889951，拒绝前后
IR不变；此 work 与上一版在更早位置拒绝的796807不是同一完成范围的性能比较。

最终独立诊断在第三个投影查询明确为**节点256触顶、深度仅1**。此前多个未匹配的
small PHI 依次消耗64、83、89等节点，随后又在一个候选中触顶；一端为 i64 转发PHI，
另一端为 `llvm.fshl.i32` 结果。这是LLVM自身的intrinsic，并非新增外部系统调用需求。
这次定位不是又一个33层递归拒绝。
下一步需要减少失败候选的深层试探、复用未变化的结构扫描，并区分可选精度增强与
最终表/写集合证明的必要义务；不得导出未证明事实或把子查询的预算问题隐藏成成功。
中央分发循环、六个源级不透明谓词的逐项验收及业务伪代码仍未完成。

四次真实回放没有新增 C/Unicorn/native Guest 执行，旧机器状态证据没有重跑或重计。
无新指令差分或全69输入语料 campaign。ROCK证据为
`~/vmc-runs/phi-forward-depth-20261115-v1/`、`v2/`、`v3/`（后两项同完整前缀）；
