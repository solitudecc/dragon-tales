# 有限写入足迹与同一快照的表达式界

2026-11-09，基线 `401ece6`。本阶段改进静态有限值分析对内存写入的处理，
不改变公共 API、IGNIL 操作码、Guest ABI、指令提升器或 LLVM 优化器。
规则同时用于 `prove_leaf_calls=False/True`，不依赖可选 Z3。

## 保留写入范围以外的事实

旧实现只接受唯一写地址和至多 64 位的数据；其他 STORE 会清空全部内存事实。
现在对完整有限地址集合求可能写入字节的并集，仅失效这一区域。
多个候选地址是弱更新，不能将写入值安装到每个候选地址；只有唯一地址可以强更新。
部分覆盖的旧标量槽按字节保留未写部分。

数据宽度超过 64 位时，分析仍不计算其有限值集，但可以使用已知地址和实际写入
宽度保留不重叠的内存。IGNIL 的 `Width` 是八位无符号数，本阶段实际测试至 255 位，
不将无法表达的 256 位冒充为已支持。255 位写入按 32 个字节失效，不先将宽度舍入
成会溢出的 256。零宽或未知地址保持全部内存屏障，不同的未知符号基址仍可能别名。

同一指针空间中的足迹采用模地址区间，使用起点距离判定相交，包括环绕。
标量单地址路径保留原逻辑计数，新增的候选和宽足迹扫描消耗操作预算。
STORE 拆分旧槽会增加事实数量，因此现在也在 STORE 后立即检查事实预算，
即使它是无后继、无查询块的最后一个操作，也不能跳过该检查。

## 同一快照的数学界

对等宽 1～64 位整数，恒有：

```text
((x | mask) - x) mod 2^width = (~x) & mask
```

右边只可能取 mask 的子集。只有完整结果域不超过 `maxValues` 时才枚举，
不截断候选。例如 mask 为 7 时结果始终在 0～7 内，不需要知道 x 的具体值。

私有块内快照 DAG 穿过等宽 COPY 和寄存器中转，跟踪 Temp 的实际到达定义。
独立 LOAD、UNDEF 和不支持的定义分别生成不透明叶；不会因为抽象值都 Unknown
就认为它们相等。部分寄存器写、32 位写的父寄存器清零及 CALL 会使对应寄存器
快照失效，已捕获的 SSA Temp 保持其原值身份。宽度变化、块局部控制流、未提升
块或非法副作用定义不能借此得到证明。

每次分析仅按不可变块缓存静态结果；缓存项及其枚举值计入事实预算。
构建临时存储至多 65536 个逻辑事实、8192 个节点，并受当前剩余事实预算限制。
扫描、快照处理、节点和结果生成均计费，失败费用不退回；局部失败不发布半份计划。
应用结果与既有有限值取交集。原有 64 值、4096 块、1000000 操作及 262144 事实
默认限制不变，全局预算失败仍使全部结果 Unknown。

这不改写 IR，不恢复一般表达式关系、任意符号循环、堆对象或初始化效果。
分析仍针对固定代码；未新增自修改代码或操作系统故障模型。

17 个用例中 11 个失败、2566 条断言失败；旧无 Z3 的原 16 个用例中 10 个失败、
5662 条断言中 2554 条失败。额外的终结 STORE 预算反例只在旧主构建执行，
36 条断言中 12 条失败，没有虚报旧无 Z3 的该项覆盖。
主构建完整 CTest 为 772/772，无 Z3 为 640/640，均为本阶段实际完整运行。

独立 Z3 4.13.3 对 1～64 位的恒等式及 mask 外反证给出 128 UNSAT；
坏公式与独立快照控制给出 8 SAT，0 Unknown。另有 1396736 次小环形空间的
逐字节集合对照，区间公式差异为零。这验证数学公式，不替代 C++ 快照实现测试。

五个永久机器码夹具的独立顺序模型与 80 次完整 Unicorn 返回一致，比较 5728 个
建模字段及 5242880 内存字节。结果和内存控制各检出 80 次单项错误，DF/NF
控制分别检出 64/16 次，缺边控制检出 80 次。零排除、跳过或归一化。
AArch64 的 STR Q0 用于实际 128 位写入的 CPU 与只读有限值验证；现有
FiniteDispatchPass 只支持 x86，本阶段未把 A64 算作该 Pass 或原生恢复成功。

每配置 40 份只读报告覆盖 20 个正例和 20 个别名负例。旧主库正例均 Unknown，
新主库及无 Z3 正例均精确为目标 0x1100；可能覆盖表的负例仍 Unknown。
查询没有使用 CPU 观察目标作入口提示或初始内存，表值来自客体自己的 STORE。

四个 x86 夹具的两种策略、O0/O2、16 个输入及各执行模式合计 1024 次完整
原生 root 匹配，比较 65536 个建模字段和 67108864 内存字节。
结果、单字节内存及缺边控制各 64 次；缺边控制的 64 次原生执行仍完整匹配，
被删空的唯一目标 publication 全部检出。所有正常输入与 192 次控制分开统计。
旧版对应的 256 次均提前 Transfer，原始失败状态保留；四次先行观察另列，
不称为旧版完整函数语义错误，也不把它们计为新版成功。

## 真实 Tigress 的条件收益

复用冻结的八个 CPU 执行前缀及原入口约束，未重跑 CPU、未注入堆快照或执行
megaInit。两个构建各 16 份只读报告全部在原预算内完成，操作数 700828～921926，
Graph 指纹保持一致。每配置由上一阶段 96 Finite / 96 Unknown 改善为
160 Finite / 32 Unknown，两个配置逐字段结果一致。

实际丢失点是 `0x100d4` 的输出写入：索引为 `(x|7)-x`，原先被当成任意地址。
输出与表不重叠的八份报告现在各有 12 Finite / 0 Unknown；输出与表重叠的
八份报告各有 8 Finite / 4 Unknown，保留真实可能被覆盖的四个表单元。
x86 的向量写入已拆成两个 64 位 STORE，不能将本例的改善误归因于宽 STORE。

这些是当前 Graph 上的条件查询，不是完整 kernel 返回、无条件表发布或一般
堆分析。独立 CPU 前缀是重用的见证，不计为本阶段新增完整执行样本。
