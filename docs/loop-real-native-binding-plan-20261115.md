# Real Loop view native binding plan — revision 3

This is a preparation plan, with no after-native executions claimed. An
after campaign may start only from a frozen production result with
`closed=true`, `changed=true`, `budgetExhausted=false`, valid whole-module IR
and unchanged ordinary functions. A private hypothetical CFG is not eligible.

The before calibration remains the existing16 inputs, complete66136-byte
Unicorn reference frames and O0/O2 native comparisons. Its driver source SHA is
`e0fb71e08b117ddb6c929dc60ff66af938073695ced0fe68b6f50aa9c69c75bb`.
Production after IR and any later cleanup pipeline are separately pinned and
separately validated. No reference frame or comparison byte is normalized.

## Bind every actual entry

The frozen original wrapper `dragon_static_entry_x86_64_1000` contains exactly
one direct call to `dragon_static_entry_x86_64_1010`, with the existing
`dragon.guest.call.target` attachment. Thus changing only the C driver's4112
target entry and external-call handler would leave this direct path running
the ordinary kernel. An equal output alone would not validate the new view.

Keep the production after module immutable. In an independently recorded
native-adapter copy, redirect only that exact wrapper call's callee operand to
the frozen closed B view. Assert there was exactly one such call in the
wrapper, that the function types match and that no other instruction,
metadata, ordinary-kernel body or global changes. The closed view's guard-miss
call to the ordinary1010 root must remain ordinary. Its recursive references,
if present, are not rebound. Verify the entire adapter module and save its
exact difference from production IR.

The C driver additionally declares the closed view by its exact LLVM symbol
using a C asm alias, and redirects only its4112 target-table entry and4112
external-dispatch call. The ordinary1000 initial entry, execution context,
registers, Guest bytes, budget and full output framing remain unchanged.
Preserve the before driver and record the exact adapter source difference.

## Prove the closed view executed

A separate observer copy adds only two volatile host counters at the actual
accepted and ordinary-fallback sites. It uses a separate sidecar; the complete
66136-byte output remains the original format. Audit the exact instrumented
sites and code difference before compiling. For all16 unchanged inputs under
both O0 and O2 require one accepted hit, zero fallback hits and an exact full
state match. Neither counter data nor an observer-only execution replaces the
unmodified production-adapter native campaign.

SP and table guard misses must hit the ordinary fallback and match the
ordinary-root oracle on the same altered input. Logical Guest-size/null
boundary drivers are separate cases with explicitly recorded kernel entry;
the wrapper may fail before reaching the kernel and cannot establish a kernel
guard observation. Do not reuse changed-input results as unchanged-input
Unicorn counts.

The raw assembly initializes the first dispatcher index to48. Its first lookup
is at Guest8192+48*8=8576. A guard-miss control can corrupt this actually used
entry to an unknown target. First compare the honest adapter and ordinary
module on the altered frame. A separate valid-IR fault control bypassing the
relevant table checks must then be detected by the full-state comparator;
save the observed mismatch, not just the intended mutation. Every changed
comparison for the corrupted bytes must be identified. This does not authorize
changing production guards or proof inputs.

Keep all register/Guest/Exit corruption controls and frame-field audits. Count
ordinary runs, production-adapter runs, observer runs, altered-input controls
and fault-injected executions separately. Archive compiler commands, exact IR,
driver/header/runtime hashes, inputs, outputs, sidecars, resource limits and
failures on both hosts. Full-state equality plus actual accepted hits is still
not a structural proof that the dispatcher loop disappeared; that is a
separate inspection of the accepted view after the documented cleanup recipe.
