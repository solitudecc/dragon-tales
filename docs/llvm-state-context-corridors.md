# 多级状态上下文与地址关系

基线 `947f9c1`。本阶段延长显式 `dispatch-specialize` 中已证明的状态入边，
让其上下文经过共享桥接块、后续 PHI 和内存检查。默认优化顺序、Graph、机器指令、
Guest/C ABI 和表内容假设均保持原契约。

## 具体缺口

上一阶段已能证明首检查上某条入边的状态为 50，但后续共享桥接块和第二个 PHI
再次将它与其它状态合并。真实 f-cff O2 的表地址为 `69696 + state * 8`；
对已知入边应能表示为 Guest 偏移 70096，同时保留运行时内存大小检查、实际表项
LOAD、目标 switch 和默认退出。把 ELF 字节或一次重放结果当作表内容不变性仍不成立。

## 改写契约

从一条已证明条件恒定的首检查入边出发，在同一次改写中复制有界的后续安全路径。
沿实际选定的前向边替换 PHI incoming，保留纯计算和 simple LOAD。后续条件未知时
仍执行完整的条件分支；不会为了继续传播状态而假定边界检查成功。

终端目标 switch 的 cases/default 保留。回到较早区域块或自身的目标进入原块，重新
执行 PHI、LOAD 和 freeze，不回到当前上下文副本。原未知路径保持可达，外层条件、
失败出口、块外及循环使用需要完整 SSA 修复，外部 SSA 值保持原身份。

延长不成立时保留原有单块特化能力。表达式证明、复制、SSA 修复和重复运行均需有界；
未证明的 poison、调用、写入、同步、volatile/atomic、EH 及旧执行依赖保持保守。
统计中的已折叠分支与保留条件的上下文副本分开解释；复制 target switch 不计为
消除了分发器。

## 验证状态

生产、回归和独立模型由三个 agent 分开实现。最终同源测试对冻结旧库为
**14 cases / 388 assertions，8 cases / 45 assertions 失败**；修复库为
**14 / 580** 全过。原有 21 个状态检查测试未改动，合并组 main/no-Z3 均为
**35 cases / 2798 assertions**。完整 CTest 分别 **951/951、816/816**，包含
已有 UBSan targets。没有用无法编译或无效输入 IR 代替旧代码失败控制。

独立原生矩阵包含 9 种模式、1728 个固定输入，before/after 各以 O0/O2 编译执行，
新旧两库各 **6912 次**完整返回值、调用计数、512 字节寄存器、64 KiB Guest 和七字段
Exit 比较均匹配。新库四种正模式保留未知 bounds，同时将表 LOAD/检查各从 1 份变为
2 份，并通过已知索引和 switch reentry 检查；五种效果屏障保留原单块收益，不延长。
1920 个故障 IR 观测中的 **486/486** 个预定差异全部检出，另有 **19011** 个单字段及
长度比较器控制。输入含两个合法目标、回首块/后续汇合及未知 default，回入次数有明确
有限预算，不给 poison/undef 指派固定原生值。

旧单块矩阵在既有纯语义模式下复验 **4928/4928** 匹配，**312/312** 指定故障检出。
原来的“恰好一个副本”精度 gate 保持原样；它不适用于新增多块能力，未被改成宽松检查。
新矩阵独立验证实际多块形状。正常比较没有新增排除、跳过或归一化。

四个冻结 ELF 的原顺序与 post-GVN GuestSSA 流水线，新旧各自重放均为
**C16/LLVM16** 完整根匹配，Graph、输入、库哈希不变。两条新流水线都只在 f-cff O2
增加本轮上下文收益：已知 50 路径经过复制的桥接块和第二个汇合，未知 bounds 仍依赖
实际复制的 LOAD；目标 LOAD 的 Guest 偏移经现有 LLVM cleanup 化为 **70096**，
且该值实际被 target switch 使用。49 个 cases、default、回原块目标和全部原入边保留。

f-cff O2 的实际 CFF switch 为 **1→2**，其中一个是上下文副本；程序自身 switch
仍为 **1→1**。其它三个样本没有本轮新增上下文收益。三个整模块仍报告 dispatch
条件预算 incomplete；GuestSSA 原顺序两个、post-GVN 四个模块 incomplete。执行匹配、
上下文精度与分析完备性分别报告，没有把副本计作分发器消除。

## 预算和中间失败

一条上下文至多 6 块、合计 256 条指令，模块至多 64 个复制块、16384 条复制指令及
262144 个 SSA 修复单元。每块入边/目标至多 512，每条路径 live-out 至多 128、
外部使用 8192；
表达式仍为 128 位、64 层和模块 65536 节点。下游有用 PHI 证明与首检查共享公开
`maxExpressionNodes` 的剩余预算。预算不足保留原单块证明能力并显式报告 incomplete。

只在下游 PHI 的实际入边上下文可证明得到整数常量时延长，避免无收益复制。遇到多个
安全后继时，以 switch、条件检查、无条件桥接的结构顺序选择一条前向延长路径；
未选出口保持原路径，未知条件继续执行，选择复制对象不代表假定其执行成功。
所有新副本不参与当前调用的候选遍历；回原块后重新取值，不构造副本间循环。

第一版在两个安全出口处过早停止，被保持不变的独立精度 gate 拒绝，尚未执行新矩阵
native，不能计作语义通过。它还复制了不产生常量上下文的旧测试后继，原测试按既有
边查询 PHI 时 SIGSEGV；gdb 确认发生在测试的不存在边查询，之前 IR verifier 已通过。
最终通过有用上下文 gate 恢复该旧结构，未改旧测试或放宽其断言。

回归夹具曾产生 i64→i128 的非法 trunc，已纠正为真实扩展；该构造失败及最初缺 Catch2
include 的编译失败单独保留，不算旧生产错误。最终旧/新统计均使用同一份有效源。
独立测量脚本的一次 regex 统计错误也单独保留，最终结果经实际 IR 和哈希复核。

文本 `opt -passes=instcombine` 的 fixpoint 检查与框架 C++ 默认选项不同：同一冻结旧
输入也报未到 fixpoint。匹配 C++ 默认的 `instcombine<no-verify-fixpoint>` 探针通过，
未改变生产优化默认值。另行 max-iterations=4 的结果不冒充默认流水线证据。
默认表达式预算 128 的两个 O2 源码探针与预算 256 的输出逐字相同，均完整且无预算耗尽；
这些结构探针与真实集成重放分开计数。

本轮没有更改默认优化、指令 lifter 或 Graph，也没有新增 69 输入全语料库/单指令
campaign。剩余多路径状态、内存不变性及其它复杂分发关系仍需证明。
