# CET 落点与函数边界

2026-11-06，基线 `70a1fab`。本次修正 x86-64 函数识别：单独的 `ENDBR64`
不再作为独立函数入口证据。真实 GCC computed-goto 代码在同一 `kernel` 的内部标签
也有这个指令；旧识别把这些标签拆成函数，使静态 IR 在块间退出。

## 识别规则

`X86Info::isCommonFunctionPrologue()` 仍识别 CET 落点模式，接口与返回值不变。
`X86Analysis` 在认定函数时区分证据：

- 原始分析根、显式 AnalysisHints 入口和直接 CALL 目标继续成为函数入口。
- `ENDBR64; push rbp; mov rbp,rsp` 等完整帧序言仍参与既有序言识别。
- 仅有 `ENDBR64` 时继续分析，不据此添加函数或人为添加基本块。
  基本块仍由真实控制流目标及原有规则建立。
- 既有 RET 后的独立布局证据仍可发现无帧叶函数。初版错误地把所有 CET 落点先设为块，
  阻止了这条规则；新增保护用例抓到两条失败断言，最终不再强制添加这些块。

没有按 Tigress 的变量、函数名或地址匹配，也没有查询导入名来假设 noreturn 或
returns_twice。CALL 的保守效果、指令语义、Guest ABI、LLVM 优化器与有限值集算法不变。
显式声明的入口优先，调用者仍须对自己提供的入口契约负责。

## 回归与完整执行

五项 C++ 回归覆盖连续/跳转内标签、显式入口、真实 CALL、完整帧和 RET 后叶函数。
旧实现 55 条断言中 20 条失败；最终 55/55 通过。中间版本的 RET 后召回问题与失败日志
单独保存，没有计入最终通过结果。

永久机器码夹具覆盖三种情况：函数内顺序落点、直接跳转落点和 CMOV/computed-goto 落点。
两个扫描策略 × V2/static/product × 原生 O0/O2 × 八输入，新版 288 次完整根返回与
Unicorn 的全部 76 个建模字段和完整 64 KiB 内存匹配；旧版对应 288 次均提前退出，
不能记为已完成函数的语义错误。无 Z3 构建另有 48 次完整匹配。返回值、内存负对照
各检出 12/12 个单字段差异，零新增排除、跳过或归一化。

CTest 602/602，无 Z3 477/477；Python pipeline/hints、守卫和寄存器/内存/循环切片
复验均通过。指令 lifter 和执行器未变，未额外重跑完整单指令语义活动。

## 真实 Tigress 的收益与覆盖变化

使用上一阶段冻结的原始 helper 调用版本，Tigress 2.1 seed 1901、goto/indirect、
C O0/O2、Clang/GCC、两种策略及六个 LLVM 计划。没有重新生成或修改这些 ELF。
每个编译器/策略组每版本 64 次 C 规范匹配、384 次 LLVM 尝试。

| 组 | 档位 | 旧版完整匹配 / 不完整 | 新版完整匹配 / 不完整 |
|---|---|---:|---:|
| GCC 两策略分别 | goto O0 | 32 / 64 | 96 / 0 |
| GCC 两策略分别 | goto O2 | 96 / 0 | 96 / 0 |
| GCC 线性 | indirect O0 | 32 / 64 | 0 / 96 |
| GCC 线性 | indirect O2 | 32 / 64 | 0 / 96 |
| GCC 递归 | indirect O0、O2 分别 | 0 / 96 | 0 / 96 |
| Clang 两策略分别 | goto O2 | 96 / 0 | 96 / 0 |
| Clang 两策略分别 | 其余三档分别 | 0 / 96 | 0 / 96 |

GCC 的额外函数入口从线性 42 / 递归 15 降为两者 0，Clang 保持 0。
四组每版本合计 256 次 C 匹配；LLVM 由 512 完整 / 1024 不完整变为
576 完整 / 960 不完整。完整执行差异、基础设施错误、未执行比较和 unlifted 均为 0。

GCC 线性 indirect 的 64 次覆盖下降必须保留：原先错误拆出的函数片段被 V2 当作独立
恢复入口使用。纠正函数划分后，未证明的分发目标仍不能把这些代码纳入根函数。
这里需要后续目标证明或独立的块入口视图能力；不能把这些提前退出计为通过。
本次不宣称恢复了 indirect、初始化堆、不透明状态或完成去平坦化。

## 真实语料审计

两个真实语料库的 69 个输入、138 种策略全部完成。旧库另存函数入口清单，新库对每个
有效函数生成原始 V2 IR 并 verify；受影响函数的 86 次静态提升还分别在优化前后
verify，共 172 次静态模块检查。没有按函数数目截断或跳过输入。

| 语料 | 输入 | 新版有效函数检查点 | 新版原始 V2 模块 |
|---|---:|---:|---:|
| corpus | 34 | 91517 | 755 |
| corpus2 | 35 | 113889 | 920 |
| 合计 | 69 | 205406 | 1675 |

旧版对应 206649 个函数检查点、1686 份模块。减少的 1243 个候选入口分别是
121 个位于 ELF 符号函数体内的地址，以及 1122 个位于 PLT 区域的无独立符号候选
（`.plt` 1071、`.plt.sec` 51）。PLT 候选没有完整普通函数范围真值，不能把它们全部
宣传成错误入口；本版撤销了仅凭落点标记的函数推断。程序对这些入口的动态使用仍可能
需要显式入口提示、加载器元数据或后续块入口视图支持。

机器指令字节/分类、直接与已解析跳转和调用边的流式 SHA256 前后均相同；没有丢失已解码
指令。符号（含可用的未 strip 对照）、真实 CALL 及显式根的 172570 个受保护入口检查点
均保留，符号召回和无效函数数量没有退化。每个输入的无效函数数量与旧版相同。

有 1164 个撤销的候选地址未归入当前已恢复函数，其中 1163 个未归入当前有效基本块。
它们仍在解码清单中；未知控制流没有被虚构成函数内边。这一数量和 PLT/未知入口限制
全部保留，不把“少生成函数”当成执行覆盖增加。所有新版有效函数均提升成功，V2 和上述
静态 IR 均合法；这些检查不证明整个语料的运行语义。

三个已有 Lua 基准的未提升总数和完整形式直方图保持一致：i386 188、x64 49、A64 90。
本次没有重跑完整单指令/真实块语义活动，也没有把两个语料库的所有函数都重跑静态优化；
变化定义的静态检查与原生函数对拍覆盖本次改变的函数划分路径。
